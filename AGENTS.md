# MCF bootstrap pointer

Discovery bridge only; canonical authority remains in `project-instructions/`, `docs/protocols/`, and the project registry.
For any request to continue a named project, first resolve the requested name against `context/projects/*.yaml` using project id, aliases, and canonical repository. An exact registered alias match determines the target project. Do not substitute the MCF repository's own workstream merely because MCF is the current repository or contains the registry; select MCF itself only when the request actually names MCF/the framework.
After selecting the registry entry, bind a TARGET_REPOSITORY_ROOT to the checkout for that entry's `identity.canonical_repository`. Before declaring it unavailable, search the current workspace and sibling/child repository directories for a unique checkout matching the canonical repository name; verify the candidate with its project capsule/canonical entrypoints and, when available, its git remote. If exactly one candidate matches, bind it as TARGET_REPOSITORY_ROOT. If none or multiple ambiguous candidates remain, perform discovery only and do not modify files.
From that point, interpret `context.capsule_path` and every `context.canonical_entrypoints` path relative to TARGET_REPOSITORY_ROOT, never relative to the MCF repository. Do not substitute MCF's own capsule/status/next files for the selected project's files.
Before any write, read `project-instructions/MCF-PROJECT-OPERATING-INSTRUCTIONS.md`, apply `project-instructions/MCF-STARTUP-CHECKLIST.yaml`, then load the selected project's capsule and canonical entrypoints from TARGET_REPOSITORY_ROOT. If bootstrap is incomplete/conflicted, perform discovery only and do not modify files.
