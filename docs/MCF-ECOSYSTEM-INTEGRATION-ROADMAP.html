01 / VISÃO ATUAL

O que já virou ecossistema

Pense em uma estação: o MCF é o centro de controle, o Ledger é o arquivo, o TriView é o painel e o Cloud é a casa de máquinas. O painel já sabe onde cada peça está, e as duas passagens read-only funcionaram no laboratório. O inventário estrutural 4/4 já passou; depois do merge, as fichas semânticas serão atualizadas antes de repetir a conferência final.

O MCF já possui contratos, schemas, Registry dos quatro projetos, leitura de Capsules, verificação de freshness e dois endpoints GET-only protegidos. O CF-0/CF-1 foi incorporado ao main no PR #153; CF-2 e o Capability Registry estão IMPLEMENTED_AND_VERIFIED_IN_BRANCH, com recovery estrutural 4/4 PASS. Isso ainda não sincroniza semanticamente as Capsules com o futuro estado pós-main.

O Cognitive Ledger comprovou a rota final de três operações pelo AppModule, com token próprio, raw bloqueada, 3 auditorias, memória não persistida e nenhuma API paga. O TriView já apresenta recovery e capabilities de forma read-only no branch de release. O Cloud teve o PR #26 integrado no branch lab, e o cliente real do MCF passou 3/3 testes E2E contra o processo stdio descartável. O G2-B permanece deliberadamente inativo.

Portanto, “implementado” não significa automaticamente “conectado”, “autorizado” ou “verificado”. Essa separação impede que um agente trate código existente como permissão operacional.

Como ler os estados

Verde é evidência fechada. Azul é a próxima integração. Violeta é planejamento. Amarelo exige gate humano. Vermelho está fora desta entrega.

04 / GUARDRAILS

Regras que não podem quebrar

Estas regras transformam integração em cooperação segura, em vez de dar uma chave mestra a cada agente.

01

Owner por verdade

Registry identifica; cada repo mantém seu contexto; Cloud mantém estado operacional; Ledger mantém memória auditável.

02

Read-only degrada; write fecha

Leitura pode informar stale/offline. Escrita nunca continua por cache, suposição ou evidência histórica.

03

Freshness visível

Repo root, HEAD, worktree e observed_at acompanham a afirmação; snapshot não se fantasia de estado live.

04

Segredo fora do contexto

Tokens ficam em variáveis/secret stores. Capsule, Registry, Ledger, Receipt e TriView guardam apenas referências seguras.

05

Bootstrap independente

O MCF recupera identidade mesmo com Ledger, TriView, provider de IA ou Cloud offline.

06

VPS é outro boundary

Continuidade da VPS segue em frente paralela preservada. Nenhuma evidência local aqui concede acesso ou altera o ambiente.

05 / CUSTO ZERO

IA sem cobrança por API

Custo zero é uma restrição arquitetural: nenhuma rota automática pode cair silenciosamente em provider pago.

R$ 0 chamadas pagas e embeddings nos E2Es Ledger observados

Política operacional

  • ChatGPT pode continuar sendo a interface humana atual, sem exigir chave paga dentro dos serviços.
  • Embeddings pagos ficam estritamente opt-in e desabilitados no caminho padrão.
  • Busca estruturada, leitura repository-native e fallback local continuam disponíveis sem provider externo.
  • Qualquer API gratuita futura deve ficar atrás de adapter neutro, quota explícita e fallback offline.
  • Testes de integração devem provar zero chamadas pagas, não apenas confiar em configuração.
Evidência final MCF → Ledger: o provider mantém 4 tools, mas o MCF allowlista 3. O E2E fez 3 operações, gerou 3 auditorias, bloqueou raw, manteve o fingerprint 953cf4f346240c029c3bcd584d02eed0 e registrou 0 embeddings/0 chamadas pagas.

08 / RISCOS

Onde ainda podemos nos enganar

O risco principal agora é promover evidência de laboratório para autoridade operacional ou confundi-la com merge, staging e estado remoto atual.

ALTO · ESTADO

Implemented vira active por atalho

Exigir conexão, autorização, verificação e timestamp válidos antes de ACTIVE.

ALTO · EVIDÊNCIA

Task 8 vira VPS pronta

Manter G2-B como LAB_VALIDATED_INACTIVE; Tasks 9/10 e VPS seguem fechados.

CRÍTICO · AUTORIDADE

Cockpit ganha mutação

TriView continua GET-only; nenhuma credencial de bridge, shell ou segredo na interface.

ALTO · MEMÓRIA

MCF duplica memória bruta

Adapter Ledger devolve leitura efêmera; o MCF não persiste o payload, apenas contador técnico de abuso sem conteúdo, e o Ledger permanece owner da memória.

MÉDIO · FRESHNESS

SHA histórico parece live

Proveniência e observed_at acompanham toda claim; escrita falha fechada se a evidência expirar.

ALTO · CUSTO

Fallback aciona provider pago

Provider pago desabilitado por padrão, sem fallback automático e com auditoria de zero chamadas.

ALTO · PARALELISMO

Branches concorrentes se atropelam

Integrar por commits/contratos, preservar worktrees originais e publicar handoffs com SHAs exatos.

MÉDIO · DEPLOY

Merge dispara ambiente inesperado

Auditar workflows antes do merge; aceitar somente lab/staging explícito e provar que o runtime de produção permaneceu intocado. Vercel estática é outra classe, sem runtime/API do MCF.

ALTO · TCB

Isolamento Python parece sandbox

Os 16 arquivos e o venv medidos provam integridade daquela execução. python -I/audit hook não atestam toda a supply chain nem criam sandbox de sistema operacional.

ALTO · VPS

Frente paralela perde isolamento

Continuidade da VPS mantém owner e missão próprios; esta entrega não lê nem altera NODE-01.

Adapters reais
