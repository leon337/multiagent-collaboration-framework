## Architectural interpretation
Dots’ published contract combines a persistent work environment, connected tools, context continuity, read-only proactive research, risk-sensitive action rules and a separate action review mechanism. MCF’s current repository emphasizes mission contracts, explicit skills/providers, persistent external-action state, receipts, human-control policy and mandatory audit artifacts. They overlap in governance goals but are not the same architecture.

## Prioritized MCF opportunities (proposals, not statements of existing code)
1. **Action intent contract:** type every operation by resource, operation, data sensitivity, reversibility, recipients, scope and mission version.
2. **Policy Decision Gate:** emit an auditable decision with allowed / denied / requires confirmation / handoff / safe alternative / stop, then enforce it outside model-controllable execution. Agent text cannot override it.
3. **Read-only research capability:** disallow mutating operations at tool/adapter level during research, with a separate gate for any follow-up action.
4. **Scope lineage:** bind delegation to the exact task, user authorization, context snapshot, memory source, expiry and revocation state; do not broaden scope through chained tasks.
5. **Activity and interruption:** unify current mission timeline, provider state, action reservation, evidence and reason for pause into a visible stop/resume/redirect model.
6. **Memory lifecycle:** define provenance, minimization, cross-context transfer, revocation, retention, correction and deletion propagation.
7. **Red-team regression suite:** test prompt injection in third-party content, changing permissions during work, cross-task contamination, action-review rejection, ambiguity and external outcome UNKNOWN.
8. **Security gate:** keep dependency audit mandatory; current Issue #427 means this cannot be treated as passing.

## Important limits
This is a contract-level comparison using the reviewed public docs and selected MCF files, not a full source-to-source or runtime benchmark. “Not evidenced” means the inspected evidence is insufficient. No internal Dots implementation is asserted.
